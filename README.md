# Технічна специфікація (Specification) — Інтернет-магазин автозапчастин

Цей документ описує архітектуру, модульну структуру, схему даних (з урахуванням документоорієнтованої специфіки MongoDB) та ключові сценарії взаємодії для вебзастосунку інтернет-магазину автомобільних запчастин.

---

## 1. Архітектура, компоненти та модулі

Застосунок побудований за класичною клієнт-серверною архітектурою з використанням **Vanilla JavaScript** на фронтенді та нативного **Node.js** (без сторонніх фреймворків на кшталт Express) на бекенді. Для роботи з базою даних використовується офіційний драйвер **MongoDB Node.js Driver**.

### Модульна структура проєкту:


3.  Ключові сценарії та оновлення даних
    Сценарій 1: Реєстрація та авторизація користувача
    Клієнт: Користувач заповнює форму на auth.html (email та пароль) і надсилає POST-запит на /api/auth/register або /api/auth/login.

Сервер (authController.js): Перевіряє наявність користувача, хешує пароль за допомогою нативних модулів Node.js (crypto) та генерує сесію/токен.

База даних: Зберігає або зчитує документ із колекції users.

Сценарій 2: Перегляд детальної інформації про товар (Картка товару)
Клієнт: Клієнт клікає на товар у каталозі, відкривається product.html?id=XYZ. Скрипт productDetail.js робить GET-запит на /api/products/XYZ.

Сервер (productController.js): Нативний драйвер MongoDB шукає документ за \_id.

База даних: Повертає повний документ товару, включаючи його унікальні динамічні характеристики з поля attributes (наприклад, для мастила: клас в'язкості, об'єм).

Клієнт: Динамічно рендерить специфікації на сторінці.

Сценарій 3: Додавання товару до кошика та оформлення замовлення
Клієнт: Користувач обирає товар у каталозі або на сторінці деталей (productDetail.js) та натискає «Купити». Товар додається до локального стану кошика та зберігається в localStorage.

Клієнт: На сторінці оформлення (checkout.html) користувач заповнює дані та надсилає POST-запит на /api/orders через api.js.

Сервер (orderController.js): Валідує дані, створює документ у колекції orders, а також атомарно зменшує залишок (stock) у колекції products.

База даних: Оновлює залишки та фіксує замовлення.

Сценарій 4: Керування товарами адміністратором (CRUD)
Клієнт: Адміністратор через admin.html додає або редагує товар (разом із специфічними характеристиками attributes) і надсилає запит на /api/products.

Сервер (productController.js): Обробляє вхідні дані нативного Node.js та виконує метод (insertOne / updateOne) через нативний драйвер MongoDB.

База даних: Зберігає гнучкий об'єкт характеристик у колекції products.
